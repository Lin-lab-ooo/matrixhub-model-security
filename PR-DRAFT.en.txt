Draft title: Add complete model-artifact admission, bounded prefix screening and append-only human review

Model artifacts can carry executable Pickle references, unsupported serialization, truncated weights or an old scan result that no longer matches the current scanner rules. The proposed integration binds complete antivirus and static structural evidence to immutable revision content, and checks that evidence on supported downloads.

The scanner runs ClamAV 1.4.6 and Picklescan 1.0.5 in a restricted Linux service. It never loads a model or deserializes an untrusted object. A finding and complete coverage are separate facts: failed or unsupported analysis cannot become approval. Reports, tasks, policies and audit evidence are visible in the model security UI, and compatible metadata is exposed through the official Hugging Face client APIs.

The current v12.1 change introduces an optional, bounded legacy-Pickle prefix probe. It can reject already-invalid metadata while an artifact is being staged; inconclusive results remain pending and never create complete/cacheable evidence. The request and response bind the prefix hash, length, source length and scanner generation. A shared cancellable permit prioritizes full scans, with a strictly typed bounded busy retry. Older scanners without the new capability keep the complete-file path; the application adapter must be upgraded before the new scanner.

The application now overlaps staging a bounded next batch with scanning a sealed prior batch. If the next declared source will overflow the pending byte budget, the pending batch is handed off before that source is staged. The declared size affects scheduling only: the existing actual-artifact checks, resource reservation, cancellation/join, full SHA verification, final generation check and immutable revision admission remain. This is cross-file pipelining and early negative screening; it does not claim complete antivirus scanning before EOF.
The prefix probe observes the server-side repository/LFS-to-snapshot staging stream after repository content is available. It does not perform complete antivirus inspection inline with the first HF network upload.

Human reviewers can append a bound opinion to a terminal report: confirmed risk, suspected false positive or follow-up. The server obtains actor identity from the authenticated user and verifies Editor/Admin permission plus report/revision/generation binding. Opinions append a separate record and audit event; they do not mutate machine findings, cached evidence or download admission. The UI exposes this explicitly and does not offer an override button. SQLite and MySQL schema version 3 include the review table.

Final HTTP matcher fix and evidence boundary
Real negative-method acceptance found that the default cmux.HTTP1Fast matcher excluded PATCH, closing the TCP connection before Echo could return an HTTP rejection. The candidate explicitly adds http.MethodPatch through the shared matcher and adds fresh-connection TCP regressions for the old rejection control, HTTP method classification and the actual security route. This does not introduce a PATCH handler or change review/admission permissions.
Only internal/apiserver/apiserver.go and internal/apiserver/security_review_test.go differ from the preceding sanitized candidate.
