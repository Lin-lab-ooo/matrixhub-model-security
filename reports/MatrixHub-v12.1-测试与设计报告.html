本项目把通用恶意软件检查与危险序列化静态解析接入 MatrixHub：上传形成不可变 revision，产生文件级结果及版本结论，再由服务端下载出口执行准入。扫描期间不加载模型，不反序列化不可信对象，不导入模型自带模块。通过仅表示本轮支持范围和规则下检查完成，不是绝对安全证明。

2. 完整环路：文件、证据与下载如何绑定

步骤实现与保证
上传与版本Hugging Face 客户端先完整上传并提交。服务端以明确仓库和不可变 commit 建立扫描任务，变更内容产生新版本结论。
Stage 暂存SecurityArtifacts.Stage 经 LFSGetter 读取仓库存储。Git LFS pointer 必须解析为真实内容，流式计数并计算摘要，暂存结果封存后才交给扫描器。
有限前缀预检适用 legacy 文件首个 64 KiB 可交给隔离预检。只有已证明不合规才能提前拒绝；pending 表示继续读取，绝不生成完整通过或下载许可。
完整检测非特权、只读、无网络扫描器保留完整 AV、格式结构及有限构造语义检查，扫描前后摘要与规则身份校验用于发现过程中变化。
汇总与缓存文件摘要、扫描器 generation、内容清单与仓库版本共同决定证据有效性。缓存复用不意味着跳过新 revision 的完整汇总、权限及最终门禁。
服务端准入明确区分 pending、scanning、pass、warn、block、fail；缺失、过期或不完整证据不能成为安全通过。客户端获得稳定错误，旧安全 commit 与新风险版本分开判断。

静态检查分两层。pickletools.genops 只解码操作码；符号栈跟踪 GLOBAL、STACK_GLOBAL、memo 与位置，Picklescan 对实际观察到的全局引用分类。发现“引用”不等于证明已经调用，更不能声称现场执行了攻击。ClamAV 独立检查通用恶意软件特征，两类证据共同进入版本报告。

针对受限 legacy PyTorch CPU tensor，有限语义机把 storage 和 _rebuild_tensor_v2 的参数解释为内部描述对象：核对 storage 类型及字节宽度、numel、offset、shape、stride、空 hooks 与 metadata，并检查整数溢出和实际寻址范围。它不调用构造器、不创建真实 tensor；未知构造器或超预算输入保持不完整拒绝，不能凭函数名在白名单内就直接放行。

64 KiB 前缀预检还要求先找到完整的五段 legacy 元数据；缺段、截断或前缀容纳不下时返回 pending，交给必需的整文件检查。只有同一套元数据语义已证明不合规时才 reject。这个非对称设计能提早否定部分坏文件，同时避免把“前缀没有问题”误当成整文件通过。

本轮“边下载边检查”准确指仓库存储到扫描暂存阶段的早期否定预检，以及不同文件的暂存与扫描重叠。它不是用户首次 HfApi 上传前检查，也没有让完整 AV 对同一个增长文件真正流式扫描。合法文件仍必须完成全部检查后才能下载。

流水线优化会在下一大文件的声明大小预测批次溢出时，先提交已经封存的小批次，再 Stage 大文件。声明大小只参与调度，Stage 后仍重新校验真实长度、SHA 和资源额度；取消路径需先回收工作线程再释放快照。

跨文件流水线的调度时序和取消回收已经过测试；目前没有配对性能测量证明它使合法大文件的整体扫描稳定提速。它与坏头文件的早期停止、同内容缓存复用分别记录，不混为一个加速比例。

4. v12.1 人工复核：意见可追溯，机器许可不改变

人工复核采用追加式记录。用户在当前或历史已终态报告上选择“确认风险”“认为误报”或“需要跟进”，填写 1–1000 个 Unicode 字符。界面通过 canWrite 控制入口；服务端仍必须重新验证仓库写权限、真实用户身份、报告状态以及 revision/generation 精确绑定。评论按文本渲染，不解释为 HTML 或脚本。

POST /api/security/v1alpha1/models/{ns}/{name}/history/{reportId}/reviews 仅接受 revision、generation、verdict、comment；操作者、时间和记录 ID 由服务端生成。GET 同路径按 limit/offset 分页；不提供编辑或删除入口。复核记录与通用审计应原子追加，报告 ID、仓库、commit、generation、操作者可追溯。

认为误报不是放行操作。复核记录不修改扫描状态、缓存资格或下载策略，前端也只刷新对应仓库与报告的 reviews 查询。修复或规则更新后，需要重新得到有效完整机器证据。以下增量验收状态决定本设计在最终版本中的实际完成程度，不能用 v12 旧业务通过替代它。

9. 如何使用与复现

交付结构：source/ 是固定完整源码；reproduce/ 包含验证与复现入口；VERSION_LOCK.json 固定版本；reports/ 是中文报告；evidence/ 是显式审核的公开收据。先验证清单与全 SHA，再按 README 在全新隔离环境构建运行，使用自己的新测试账号；不要复用旧服务器账号或旧临时凭据。

顺序在解压目录执行的相对入口与前提
1 验证版本先核外部提供的 ZIP SHA256，再执行 python3 reproduce/verify_source.py。该命令检查固定源码清单的完整字节，不执行项目。
2 构建Debian 12 / Linux amd64，Go 1.26.8、GCC、Git、Node、pnpm 10.17.0、Docker Compose：bash reproduce/reproduce-linux.sh build。首次运行需要下载依赖与基础镜像，记录实际镜像 ID。
3 准备规则按 source/deploy/security-scanner/README.md 下载 main.cvd、daily.cvd、bytecode.cvd，固定 SHA；设置 SCAN_RULES_DIR 为新的绝对规则目录。在线更新工具与离线扫描器分离，不原地改规则。
4 启动新环境设置 MATRIXHUB_REPRO_PROJECT=matrix-v12-review001；执行 bash reproduce/reproduce-linux.sh up。仅接受新 project，拒绝复用其已有容器/卷；curl --fail http://127.0.0.1:3002/healthz 后在浏览器访问同址。
5 准备用户与项目仅对刚创建空卷按 README 的公开引导流程登录，立即修改引导密码，创建普通测试用户、私有项目及一次性 token。smoke 模型名必须未存在；token 使用交互输入，不能写入命令参数或交付包。
