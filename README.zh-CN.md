# MatrixHub 模型制品安全准入

[English](README.en.md) · [测试摘要](TEST_REPORT.md) · [已知限制](LIMITATIONS.md) · [版本说明](RELEASE_NOTES.md) · [发布与出处](PUBLICATION_NOTES.md) · [代码导航](CODE_MAP.md)

本项目是基于 [matrixhub-ai/matrixhub](https://github.com/matrixhub-ai/matrixhub) 的安全功能贡献快照，为私有模型仓库增加静态检查、版本绑定、下载准入和人工复核界面。当前交付版本为 **v12.1**，证据截止北京时间 **2026 年 10 月 14 日**。

模型仓库中的 `.pt`、Pickle 等文件可能在加载时调用代码。上传成功并不代表内容可以安全使用。本项目在仓库接收文件后，对固定提交中的文件进行隔离扫描；只有完整、有效且满足当前策略的证据，才能允许受保护的下载。

## 解决的三个问题

| 场景 | 具体处理 | 已验证范围 |
| --- | --- | --- |
| 正常模型发布与多版本更新 | 检查受支持格式；复用同一内容、同一扫描器版本的完整文件证据；每个提交生成自己的报告 | 真实 BERT-Tiny 权重、同模型派生分片、README-only 更新；另有合成 1 GiB 容量文件 |
| 模型加载可能执行代码 | 结合杀毒与静态反序列化检查；记录危险引用；服务端拒绝风险版本下载；人工意见不能解除阻断 | 受控无害风险夹具、真实 API 下载拒绝、旧安全提交仍可下载 |
| 文件不完整或证据失效 | 截断、坏构造参数、未支持语义不冒充完整检查；规则版本变化后不继承旧许可 | 当前应用中的不完整版本、同提交 scanner generation 切换、独立大文件前缀诊断 |

## 实现与贡献边界

```text
HF/API 上传 → 固定提交与文件清单 → 有界暂存/前缀预检
                                   ↓
                         隔离 ClamAV + 静态格式检查
                                   ↓
                         完整证据 + generation + 策略
                                   ↓
                         服务端下载准入 → UI/审计/复核
```

- **隔离检查**：扫描服务在受限 Linux 环境中工作；不通过 `torch.load`、`pickle.load` 或执行文件指定的构造函数来判断安全。
- **有限语义检查**：对支持的 CPU legacy tensor 构造参数、storage 长度、形状、步长与偏移进行静态验证。未知或不完整语义保持不完整状态，不能当作无风险批准。
- **提前拒绝**：暂存时可用前 64 KiB 判断部分 legacy 元数据已不合格。结果只有拒绝或待定，不能生成放行证据。
- **跨文件流水线**：准备下一批文件的同时扫描上一批已完成的快照；资源有上限，取消后先等待扫描退出再清理。
- **多版本缓存**：内容、大小、类型、范围和 scanner generation 匹配且旧结果完整时，复用分析。仍先完整读取文件、计算摘要并生成扫描快照；省去重复分析，再生成本次提交的报告。
- **服务端准入**：证据绑定不可变提交与当前扫描器版本；风险、不完整、缺失或过期结果不能通过受保护下载绕过。
- **人工复核**：Editor/Admin 可追加确认风险、疑似误报或跟进意见；记录绑定报告和身份，追加审计，不改变机器报告、缓存或下载判断。

**ClamAV 与 Picklescan 是第三方开源引擎，并非本项目原创。** 本项目的工作是模型格式检查增强、隔离集成、证据与版本约束、扫描调度和业务准入。当前锁定 ClamAV 1.4.6、Picklescan 1.0.5；没有宣称优化了 ClamAV 内核或发现全部未知威胁。

本次公开目录保留原始证据中的少量本机路径元数据。冻结源码里的旧报告、旧环境与镜像说明属于历史记录；当前版本与验收以根目录版本锁和最终报告为准，详见 [发布说明](PUBLICATION_NOTES.md)。

## 可以直接核验的结果

| 验证项目 | 结果 | 解释 |
| --- | --- | --- |
| 当前完整应用业务 | 794/794 断言通过 | 11 个提交、12 份报告；794 是业务断言，不是 794 个攻击样本 |
| 同提交扫描器版本切换 | 17 + 23 项断言通过 | 独立于上面的主业务计数；旧证据不继承为新版本许可 |
| 人工复核 API | 55/55 检查通过 | 权限、身份与报告绑定、不可编辑删除、机器报告不变 |
| 当前桌面 UI | 8/8 检查通过 | 1280×900 真浏览器、真实后端；不含手机完整流程 |
| 完整下载 | 27 次，共 1,180,190,711 字节 | 返回内容完整读取并核对 SHA256 |
| 视频 | 224.92 秒 | 实际 UI 操作；展示小型受控语料，BERT 与 GiB 测试另有 API 证据 |

单轮本地性能观察：含真实 BERT、派生分片及合成 1 GiB 文件的 V7 仓库报告耗时 **114.534 秒，已有 8 个文件命中缓存**；随后 README-only 的 V8 报告 **3.386 秒，12 个文件命中缓存**。这不是相同工作量的算法加速比，也不是 p95。

独立生产链路诊断中，约 1 GiB 的坏版本字段文件在源读取 **65,536 字节后拒绝，约 2.281 秒**。该数字属于服务端仓库/LFS 到扫描快照的读取过程；首次 HF 上传已经完成，不能用它宣称初次网络上传只传 64 KiB。

详见 [测试摘要](TEST_REPORT.md)、[完整中文 HTML 报告](reports/MatrixHub-v12.1-测试与设计报告.html)、[PDF 报告](reports/MatrixHub-v12.1-测试与设计报告.pdf) 和 [真实演示视频](media/matrixhub-security-demo.webm)。GitHub 文件预览不等于运行演示服务；HTML 可下载后本地打开。

## 阅读源码与尝试复现

发布目录采用完整源码快照布局，`source/` 包含 API、UI、数据库迁移、扫描器、部署文件和测试；`evidence/` 保存按路径组织的证据；`VERSION_LOCK.json` 标识被测版本。上游源码中的旧报告保留历史含义，当前结果以根目录测试摘要及上述完整报告为准。

先验证发布方给出的归档摘要，再在解压根目录运行：

```bash
python3 scripts/verify_publication.py
python3 reproduce/verify_source.py
```

第一条验证干净公开目录的全部列出文件与原交付映射；第二条核对 1,527 个源码文件的大小与 SHA256。两条都不启动服务。源码入口已在独立提取目录实际验证；这不代表完整应用已在全新机器部署成功。

完整步骤优先阅读 [本版复现说明](README.zh.txt)；上游源码内旧说明保留历史身份。构建与运行入口见 [复现脚本](reproduce/reproduce-linux.sh)、[安全部署说明](source/deploy/security/README.md) 和 [扫描器配置](source/deploy/security-scanner/README.md)。构建需要 Linux/amd64、CGO/Go、Node/pnpm、Python、Docker Compose、完整 ClamAV 规则及外部依赖。准确版本见 [VERSION_LOCK.json](VERSION_LOCK.json)。

```bash
bash reproduce/reproduce-linux.sh build
# 完成规则准备和全新专用环境配置后，再使用脚本的 up/test-* 入口。
```

**完整空缓存新机复现尚未完成，不能承诺一条命令在任意机器成功。** 默认部署的文件上限是 64 MiB；1 GiB 测试需要单独的 GB profile、clamd、资源额度和超时配置。请先阅读 [限制与复现范围](LIMITATIONS.md)。测试只使用新建专用实例与新凭据。
